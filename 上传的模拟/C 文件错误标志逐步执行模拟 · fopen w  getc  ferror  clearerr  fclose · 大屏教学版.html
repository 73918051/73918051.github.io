平台模型与关键考点
平台：64 位，小端序；char=1、int=4、指针=8。
FILE 类型：系统库内部结构体；fp 是 8 字节句柄地址，示意值 0x5A2C。
★ "w" 只写模式【戏眼】：w = 创建/清空为 0 字节，没有 + → 只能写、不能读。
　若错写成 "w+"，getc 会正常返回 EOF（空文件），不会置位错误标志，演示就失效了。
★ getc(fp) 对只写流读取是非法操作：返回 EOF(-1) 并置位错误标志（glibc 行为）。
★ getc / fgetc / getchar 三者等价：getchar() = getc(stdin)；fgetc 是函数，getc 通常是宏。
★ 错误标志 ≠ 文件结束标志：
　ferror(fp) 查询「错误标志」——读写出错时置位；
　feof(fp) 查询「文件结束标志」——读到文件末尾时置位；
　两者完全不同：读到末尾不是错误，出错也不是读到末尾。
★ ferror 三个特性：
　① 只读不写：只查询，不改标志；
　② 粘性：一旦置位就持续为真，除非 clearerr / rewind / 重新 fopen；
　③ 累积性：反映历史（曾经出过错），不是当前状态。
★ C 语言真值规则：if(ferror(fp)) 即 if(ferror(fp) != 0)；
　0 为假，一切非 0 为真；ferror 不保证返回 1，不要写 == 1。
★ clearerr(fp) 必须调用：清除粘性错误标志 + EOF 标志；
　原型 void clearerr(FILE *stream); 无返回值；不动文件内容、不动读写位置。
★ 三个清零 / 复位手段对比：
　clearerr(fp) —— 清错误标志 + EOF 标志，不动位置；
　rewind(fp) —— 回卷到文件头，同时清错误标志 + EOF 标志；
　fseek(fp, 0, SEEK_SET) —— 只移动位置，不清错误标志。
★ printf 与 fprintf：printf(...) 等价于 fprintf(stdout, ...)。
★ 错误消息措辞：本例打印 "Error reading"（读取出错），
　不是 "Cannot open"（打开失败）——两类错误要分开处理。
原程序缺陷：第 4 行 fopen 后未判空——失败时 fp = NULL，getc(NULL) 直接崩溃。
★ 好习惯：错误分支里没有 return，fclose 依然会执行——不提前返回漏掉关闭。
未定义行为提醒：严格按 C 标准，对只写流调用 getc 是 UB；
　本例按 glibc（Linux / MinGW）实际行为（返回 EOF + 置位错误标志）模拟。
★ 错误标志轨迹：0 → 1（getc 后）→ 0（clearerr 后）。
复杂度：时间 O(1)，空间 O(1)。

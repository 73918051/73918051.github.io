平台模型与关键考点
平台：64 位，小端序；char=1、int=4、指针=8。
FILE 类型：系统库内部结构体；fp / fm 是 8 字节句柄地址，示意值 0x5A2C / 0x7B3E。
★ 两次 fopen、两次判空：第 6 行（fp），第 15/16 行（fm）——一个都不能少。
★ "r" vs "wt+"：
　r = 只读（文件必须已存在）；
　w = 写（不存在则创建，已存在则清空为 0 字节）；
　t = 文本模式；+ = 可读可写（没有它读不回来）。
★ 路径转义：源码 "f:\\study.txt" 运行时是 f:\study.txt；"d:\\test.c" 运行时是 d:\test.c。
★ fgetc 第一次在循环外：第 10、21 行。
★ putchar 必须在 fgetc 之前：第 11、22 行。
★ 两次 rewind：第 12 行（读完要重读）、第 20 行（写完要读）——都是必踩的坑。
★ fgets(str1, 12, fp)：最多读 11 个字符 + \0；换行符会被读进来；文件 12 字节，! 留在文件里。
⚠ gets 是危险函数：完全不检查边界，C11 已删除；应改用 fgets(str2, 12, stdin);。
★ fputs 不补换行：对比 puts（自动补换行）。
★ EOF 是 -1：文件末尾信号，不是文件里的真实字节。
原程序缺陷：char ch1/ch2; 应为 int ch1/ch2;——若 char 无符号，-1 变 255，死循环。
★ fclose 必须配对：两个 fopen 两个 fclose；不关会丢数据、耗尽句柄。
★ return 0 vs exit(1)：从函数返回 vs 立刻终止程序并关闭所有文件。
其他缺陷：fclose / printf / putchar / fputs 返回值未检查；exit 需要 <stdlib.h>。
复杂度：时间 O(n)，空间 O(1)（缓冲区大小固定）。

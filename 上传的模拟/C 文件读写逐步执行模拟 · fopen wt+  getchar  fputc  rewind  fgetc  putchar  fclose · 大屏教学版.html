平台模型与关键考点
平台：64 位，小端序；char=1、int=4、指针=8。
FILE 类型：系统库内部结构体，本例不展开；fp 是 8 字节的文件句柄地址，示意值 0x5A2C。
★ "wt+" 三字符含义：
　w = 写模式（不存在则新建，已存在则清空为 0 字节）
　t = 文本模式（Windows 上 \n 存成 \r\n，读时自动还原）
　+ = 可读可写（没有它，后面 fgetc 会失败）
★ 相对路径 "2"：文件建在程序运行时的当前工作目录下（不是源码目录）。
★ 打开文件必判空：路径错 / 无权限 / 磁盘满都会返回 NULL，不判空就崩溃。
★ 键盘缓冲区：整行先进缓冲区，getchar 每次只取一个字符（包括回车 \n）。
★ getchar 第一次在循环外：先读一次 → 判断 → 循环里再读；不漏读不多读。
★ fputc 必须在 getchar 之前：先写当前字符，再读下一个；顺序颠倒会丢字符。
★ 回车符不会被写进文件：循环条件先判断，是 \n 就退出，文件只有 3 字节。
★ rewind 是写读切换的关键：写完位置停在末尾，不 rewind 会立刻读到 EOF。
★ putchar 必须在 fgetc 之前：先输出当前字符，再读下一个；顺序颠倒会丢字符。
★ EOF 是 -1：文件末尾信号，不是文件里真实存在的字节。
原程序缺陷：char ch; 应为 int ch;——若 char 是无符号的，-1 会变成 255，ch != EOF 永远为真 → 死循环。
★ fclose 必须配对：刷新缓冲区 + 释放句柄；不关会丢数据、耗尽句柄。
★ return 0 vs exit(1)：从当前函数返回 vs 立刻终止整个程序并关闭所有文件。
其他缺陷：fclose / printf / putchar / fputc 返回值未检查；exit 需要 <stdlib.h>。
复杂度：时间 O(n)（n 为文件字符数），空间 O(1)（只用一个字符缓冲）。

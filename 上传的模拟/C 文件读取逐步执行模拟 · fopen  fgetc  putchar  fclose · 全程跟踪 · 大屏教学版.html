平台模型与关键考点
平台：64 位，小端序；char=1、int=4、指针=8。
FILE 类型：系统库内部结构体，本例不展开；fp 是 8 字节的文件句柄地址，示意值 0x5A2C。
★ 路径转义：源码 "d:\\ys\\ms\\2.c" 里 \\ 是转义，运行时真实路径是 d:\ys\ms\2.c。
★ "rt" 打开方式：r = 只读（文件必须已存在），t = 文本模式（Windows 上把 \r\n 转成 \n）。
★ 打开文件必判空：路径错 / 文件不存在 / 无权限都会返回 NULL，不判空就崩溃。
★ fgetc 返回 int：读到字符返回 0~255，读到末尾返回 EOF（-1）。
原程序缺陷：char ch; 应为 int ch;——若 char 是无符号的，-1 会变成 255，ch != EOF 永远为真 → 死循环。
★ fgetc 第一次在循环外：先读一次 → 判断 → 循环里再读；保证不漏读不多读。
★ putchar 必须在 fgetc 之前：先输出当前字符，再读下一个；顺序颠倒会丢字符。
★ EOF 是 -1：文件末尾信号，不是文件里真实存在的字节。
★ fclose 必须配对：刷新缓冲区 + 释放句柄；不关会丢数据、耗尽句柄资源。
★ return 0 vs exit(1)：正常结束 vs 异常退出。
其他缺陷：fclose / printf / putchar 返回值未检查；exit 需要 <stdlib.h>。
复杂度：时间 O(n)（n 为文件字符数），空间 O(1)（只用一个字符缓冲）。

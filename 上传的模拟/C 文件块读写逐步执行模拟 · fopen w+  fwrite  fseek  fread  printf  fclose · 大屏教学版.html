平台模型与关键考点
平台：64 位，小端序；char=1、int=4、指针=8。
FILE 类型：系统库内部结构体；fp 是 8 字节句柄地址，示意值 0x5A2C。
★ char str[] 长度自动推断为 15：14 个可见字符 + 末尾 \0 = 15 字节。
★ strlen(str) vs strlen(str)+1：14（不含 \0）vs 15（含 \0）；+1 就是把 \0 纳入。
★ fwrite 四参数：fwrite(ptr, size, count, fp)；实际写入 = size × count；返回元素个数。
　fwrite(str, 1, 15, fp) → 写 15 个 1 字节元素 → 15 字节，返回 15。
★ fread 四参数：fread(ptr, size, count, fp)；实际读取 = size × count；返回元素个数。
　fread(buf, 15, 1, fp) → 读 1 个 15 字节元素 → 15 字节，返回 1。
★ fwrite vs fputs：前者按字节数写，\0 也写；后者遇 \0 就停。
★ fread vs fgets：前者不看内容按字节数读；后者遇 \n 停并补 \0。
★ fseek(fp, 0, 0) 回卷：第 3 个参数 0 就是 SEEK_SET 的宏值。
★ "w+" 模式：写+创建/清空；+ = 可读可写。
★ 相对路径 "a.txt"：文件建在程序当前工作目录下。
★ 打开文件必判空：第 7 行；文件不存在 / 无权限都返回 NULL。
原程序小瑕疵：第 9 行错误分支里也写了 return 0，应改为 return 1 表示失败。
★ printf("%s\n", buf) 靠 \0 把关：%s 一直输出到遇到 \0 为止。
★ buf[15..19] 是垃圾值但不影响输出：因为 buf[14] 的 \0 已经把关。
★ fclose 必须配对：一个 fopen 一个 fclose。
★ 块读写 vs 逐字符读写：块读写一次搬一整块内存，效率更高。
复杂度：时间 O(1)，空间 O(1)。
